# 执要 Agent · 用户脚本版（脚本猫 / Tampermonkey）

Edge 扩展「执要 Agent」的用户脚本复刻版。**两个文件，缺一不可**：

| 文件 | 角色 | 是否必需 |
|---|---|---|
| `zhiyao-agent.user.js` | 主脚本：悬浮球 + 面板、对话、网页操作、整页翻译、技能、历史、设置、日志 | 必需 |
| `zhiyao-agent-task.user.js` | 定时任务执行器（脚本猫专有 `@background` 后台脚本） | 只有要用「定时检查页面」才需要 |

两个脚本通过 `@storageName zhiyao-agent` **共享同一份存储**：主脚本写任务表，后台脚本读任务表并执行、回写结果与心跳。这是复刻扩展版 `chrome.alarms` 的方案——脚本猫没有 alarms API，但提供常驻后台脚本。

> 用 `@background` + 自调度循环，而不是 `@crontab`：`@crontab` 只支持一条固定 cron，而任务模型是「每个任务各自的 daily 时刻或 N 分钟间隔」。另外 `@background` / `@crontab` / `@match` 三者互斥，所以定时任务只能单独成一个文件。

## 安装

**主脚本（必装）**

1. 打开 https://scriptcat.org/ → 登录 → 「+」新建脚本
2. 把 `zhiyao-agent.user.js` **全文**粘贴进去（顶部 `==UserScript==` 元数据块必须保留）
3. 保存 → 打开任意网页，右下角出现悬浮球

**定时任务脚本（选装）**

1. 同样新建一个脚本，粘贴 `zhiyao-agent-task.user.js` 全文
2. 保存。脚本猫会把它作为后台脚本常驻运行（**注意：它没有 `@match`，不会出现在任何页面上**）
3. 回到主脚本面板的「设置 → 定时任务」，若仍显示「需要配套后台脚本」的黄色提示，说明后台脚本没跑起来——见下方排查表

> 两个脚本必须在**同一个脚本猫账号**下，并保持 `@storageName` 一致（默认都是 `zhiyao-agent`）。改过其中一个就必须改另一个。

## 首次使用

1. 点右下角悬浮球 → 「设置」→ 「模型服务」下拉选一个预设（默认推荐 DeepSeek）
2. 填 API Key → 点「测试连接」→ 保存
3. 回到「对话」提问；或点输入框上方的快捷胶囊（翻译页面 / 去除广告 / 资源探索）

没填 Key 也能用：「演示模式」会用本地 mock 走完整流程（含操作确认卡片），方便先熟悉交互。

## 与扩展版的差异

架构上，扩展是「侧边栏 ↔ 后台 Service Worker ↔ 按需注入的 content script」三层；用户脚本本身就跑在页面里，**中间两层整体消失**——页面读取、元素快照、操作执行都是直接函数调用。所以下面这些扩展才需要的东西在脚本里根本不存在：`chrome.scripting` 注入、消息协议、按 origin 申请权限、`executeScript` 的 IPC 往返。

| 能力 | 扩展版 | 用户脚本版 |
|---|---|---|
| 打开方式 | Edge 侧边栏 | 右下角悬浮球 / 脚本菜单 |
| 读页面对话（正文 / 视口 / 选区） | ✅ | ✅ |
| 网页操作（20 个白名单工具 + 逐步确认 + 任务模式） | ✅ | ✅ |
| 整页翻译替换 / 去广告 | ✅ | ✅ |
| 技能商店（24 个内置 + JSON 导入） | ✅ | ✅ |
| 媒体探测与下载 | ✅ | ✅ |
| 会话历史 / 日志（可导出） | ✅ | ✅ |
| 中英双语界面 | ✅ | ✅ |
| 演示模式 | ✅ | ✅ |
| 定时任务 | chrome.alarms，**关浏览器也在系统层保留** | `@background` 常驻脚本，**浏览器关掉就不跑** |
| 密钥「关浏览器即清」 | `chrome.storage.session` | ⚠️ 无等价物，见下 |
| 按网站授权页面访问 | 按 origin 申请 | 不需要（`@match *://*/*` + `@connect`） |

### 已知语义降级（就一处）

扩展的「记住密钥」开关关掉时，密钥存 `chrome.storage.session`，关浏览器即清。用户脚本没有等价物（`sessionStorage` 是按标签页的，开个新页面密钥就没了，不可用）。

因此本版的开关**语义重新定义**为「**仅本面板会话**」：密钥存内存变量，**刷新页面后需要重填**。默认是开启持久化（存本机），与原扩展默认值相反——这是为了可用性做的取舍。

## 排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 悬浮球不出现 | 页面在脚本注入前就渲染完了 / 被站点 CSP 拦 | 刷新页面；或用脚本管理器菜单里的「执要 Agent」入口打开 |
| `测试连接` 显示 HTTP 401 | Key 错误或额度不足 | 到服务商后台核对 Key |
| HTTP 429 / overloaded | 服务商限流或过载 | 稍后再试，或换模型 |
| 网络错误 / 请求失败 | 站点 CSP 拦了页面内 fetch，且脚本管理器跨域未放行 | 脚本内已自动回退 `GM_xmlhttpRequest`；仍失败则到脚本设置里勾「允许跨域」 |
| `请求超时：45 秒内没有收到数据` | 连上了但服务商一直不给响应头 | 换国内可直连的服务商（DeepSeek 等） |
| `请求超时：30 秒内没有收到数据` | 流式中途卡住（服务商排队或过载） | 稍后再试，或换模型 |
| 定时任务区显示黄色「需要配套后台脚本」 | `zhiyao-agent-task.user.js` 没装或没运行 | 装上下载的后台脚本；两个脚本的 `@storageName` 必须一致 |
| 定时任务到点没反应 | 同上；或浏览器完全退出（后台脚本不会在浏览器关闭时运行） | 保持浏览器运行；到点前打开过任意网页有助于后台脚本保活 |
| 整页翻译错位 | 翻译过程中滚动了页面（懒加载内容变化导致序号错位） | 重来一次，过程中别滚动——这也是面板里那条「请勿滚动」横幅的由来 |

## 与扩展版的刻意差异

复刻时发现扩展有几处确凿缺陷，用户脚本版**没有照抄**：

1. **JSON 降级模式现在支持多步**：扩展里不支持 function calling 的服务商只能走一步就终止（工具执行完会把 JSON 原文当最终回答）。用户脚本面向的服务商更杂，这条必须能用。
2. **回喂内容有上限**：扩展把 `get_texts` 的结果（最多 1000 条 × 1000 字符）原样回喂，会撑爆上下文；这里截断到 60000 字符。
3. **会话 `createdAt` 不再被覆盖**：扩展每次续聊都会重建会话对象，首次创建时间丢失。
4. **并行工具调用不再静默丢弃**：系统提示词要求每次只调一个工具，但模型仍可能并行返回；扩展会丢掉多余的且不作声（模型以为都执行了），这里会对多余的显式回喂一条说明。
5. **删掉了 `--shadow-1`**：扩展的 CSS 引用了这个从未定义的变量。

其余行为（步数上限 10 / 去广告 50、确认门与危险词三路扫描、翻译横幅、演示模式文案、系统提示词全文、20 个工具的 JSON Schema、24 个技能指令）**逐字复刻**。

复刻过程中还发现扩展内部数字自相矛盾（技能数注释写 17、关于页写 21、README 写 5，**实际 24**；工具数文档写 17，**实际 20**）。用户脚本一律以代码实际值为准。

## 目录与构建

`docs/userscript/` 下只有两个产物文件。主脚本是**单文件**（约 5200 行），其中约 2000 行是由构建脚本从扩展源码**原样提取**注入的，不是手抄：

| 注入内容 | 来源 |
|---|---|
| 中英文字典（186 条 × 2） | `extension/public/_locales/{zh_CN,en}/messages.json` |
| 24 个内置技能 | `extension/src/core/skills.ts` 的 `BUILTIN_SKILLS` |
| 20 个工具定义 | `extension/src/core/tools.ts` 的 `TOOLS` |
| 页面读取 / 快照 / 操作执行器（748 行） | `extension/public/content/*.js`（本来就是零依赖纯 JS，直接当函数调用） |
| 微信打赏二维码 | `extension/public/donate-qr.jpg`（内联 base64） |

这样扩展更新后重新生成即可，不必手工同步。生成器与测试脚本不在本目录（属开发工具，不进产物）。

## 验证

改动后用 `node --check` 过一遍语法。开发期有三套测试（静态一致性 34 项、行为单测 + 移植保真度 72 项、端到端 17 项），其中值得一提的两项：

- **移植保真度**：逐个比对用户脚本里的内容脚本函数与扩展原文件是否**逐字一致**（25 个函数）
- **端到端**：起本地 mock OpenAI 服务，让真实的 `streamChat` 走完整 HTTP + SSE 路径，覆盖工具调用参数分片拼接、非流式降级、HTTP 错误分类、空闲超时、用户中止、GM 通道回退
