## 2. AI 操作网页：怎么办（本版核心设计）

### 2.1 思路：给 AI 一副「可操作的页面地图」，而不是原始 HTML

直接让模型读原始 HTML 有两个问题：token 爆炸（页面 HTML 动辄几百 KB）、噪音大（样式/脚本干扰模型判断）。正确做法是**两层信息通道**：

| 通道 | 内容 | 触发时机 | 用途 |
|---|---|---|---|
| ① 可读文本 | 标题 + 正文（Readability 式提取） | 每次提问时 | 问答、总结、理解 |
| ② 交互元素快照 | 页面上所有可见交互元素的「地图」（JSON） | **用户提出操作意图时**才采集 | 让 AI 知道「能点什么、能填什么」 |

通道②就是「读 HTML 代码」的工程化形态：content script 解析 DOM，把 button / a / input / select / textarea / [role=button] 等交互元素蒸馏成紧凑 JSON，模型据此输出操作指令。

### 2.2 交互元素快照格式（content script 生成）

```jsonc
{
  "url": "https://shop.example.com/cart",
  "title": "购物车",
  "domHash": "a3f9c1",           // 页面结构指纹，用于复用缓存
  "elements": [
    { "i": 0, "tag": "button", "text": "结算", "aria": "",
      "type": "button", "disabled": false, "visible": true,
      "box": {"x": 880, "y": 420, "w": 120, "h": 40},
      "selector": "#checkout-btn" },
    { "i": 1, "tag": "input",  "text": "", "aria": "数量",
      "type": "number", "value": "1", "visible": true,
      "box": {"x": 700, "y": 300, "w": 60, "h": 32},
      "selector": "input[name=qty]" }
  ]
}
```

要点：
- **优先视口内元素**，总量上限 200 个（超出截断并注明）；字段全部截断，控制 token。
- `i` 是模型引用元素的**索引号**（最稳的定位方式）；`selector` 是兜底（id > name > aria-label > 唯一路径）。
- `domHash` 用于缓存：同一页面滚动/切 tab 不重复采集。
- 只覆盖**主框架 + 同源 iframe**；跨域 iframe v1 明确不支持（在确认卡片上注明「该区域无法操作」）。

### 2.3 工具白名单（模型可请求的动作）

| 工具 | 参数 | 说明 |
|---|---|---|
| `snapshot` | — | 请求刷新交互元素地图（模型第一步自动调用） |
| `click` | i / selector | 点击 |
| `type` | i, text | 输入文本（**需要用户看到全文**） |
| `select` | i, value | 下拉选择 |
| `scroll` | direction, amount / to i | 滚动 |
| `read_html` | i | 返回某元素的 outerHTML（有界截断）——「读 HTML 代码」的按需补充 |
| `read_text` | i | 返回某区域 textContent |
| `extract_table` | i | 把表格提取为 CSV/JSON 到侧边栏 |
| `copy` | i | 提取内容到剪贴板 |
| `open_in_new_tab` | url | 新标签页打开（可选） |

模型通过 function calling（或降级为 JSON 模式提示词）输出 `{"tool": "...", "args": {...}}`；**扩展内做白名单 + 参数 schema 校验**，模型想不出白名单动作（比如注入脚本）直接拒绝。绝不执行模型生成的任何代码。

### 2.4 执行器细节（content script）

- **点击**：`el.dispatchEvent(new MouseEvent('click', {bubbles:true, cancelable:true}))` + 前置 `mouseover/mousedown/mouseup` 序列——兼容 React/Vue 合成事件。
- **输入**：先聚焦，再用**原生 setter 技巧**赋值（`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set.call(el, text)`）再派发 `input` 事件——绕开 React 受控组件的值拦截。
- **下拉**：set value + `change` 事件（select2 等自绘组件标记为「可能失败」，失败回传让模型换策略）。
- **执行前二次校验**：按 i 重新解析元素，确认仍存在、可见、未禁用；索引失效就重新 snapshot 让模型重选。
- **执行后回传结果摘要**：「已点击『结算』，页面 URL 变为 /checkout，新增 5 个可见元素」——供模型决定下一步。
- 已知不可操作区域：canvas（网页游戏/在线文档画布）、WebGL、跨域 iframe、shadow DOM 会尽力穿透但标注。

### 2.5 逐步确认流程（用户要求：每次确认）

```
用户：「把购物车数量改成 2」
  │
  ▼
模型请求 snapshot → 分析 → 提议动作
  │
  ▼
侧边栏弹出【操作确认卡片】：
  ┌─────────────────────────────────┐
  │ 操作：输入                     │
  │ 目标：数量输入框 (input, #qty)  │
  │ 内容：2                        │
  │ 风险：中（修改数据）            │
  │ [ 确认 ]  [ 取消 ]  [ 编辑 ]    │
  └─────────────────────────────────┘
  │  用户确认
  ▼
执行 → 结果摘要回传 → 模型提议下一步（如「点击结算」）→ 再次弹卡片
```

- **每一步都弹卡片**，用户确认后才执行；默认无「自动确认」开关（v1 干脆不做，避免合规争议，也符合你的要求）。
- 多步任务上限 **10 步**（防 token 失控），用户可随时中止；本会话内保留「已执行操作」列表可回看。
- **风险分级标签**：低（滚动/读取）、中（修改输入/点击普通按钮）、高（提交表单/删除/支付类按钮）——高风险的卡片红色强调。
- 输入类动作**必须展示完整输入文本**（用户要看到 AI 填了什么）；涉及密码框的输入 v1 默认拒绝并提示手动输入。

### 2.6 与合规政策的对齐

- 微软政策 Bots 条款禁止「自动执行操作以操纵平台」——**逐次人工确认 + 无批量/无人值守**正是这条红线的解法；商店描述与 Single Purpose 中明确写出「所有操作均需用户逐次确认，无全自动任务」。
- 模型输出只允许白名单动作（2.3），无任意脚本执行 → 不触碰远程代码条款。
- 页面内容发送给用户配置的服务商 → 维持 v2 的 opt-in 同意 + 发送前预览 + 隐私政策。

## 3. 其余设计要点（沿用 v2，摘要）

- **架构**：纯客户端 MV3 单包（sidePanel + service worker + 按需注入 content script），HTTPS 直连用户配置的服务商，无后端、无账号。
- **权限**：`sidePanel`、`activeTab`、`scripting`、`storage` + **`optional_host_permissions`**（添加服务商时才申请该 origin）。
- **模型配置**：8 个预设 + 自定义端点；能力检测（function calling 缺失时降级 JSON 模式）；「测试连接」按钮；密钥存储按决策 2。
- **演示模式**：无 Key 时全流程 mock（问答回复 + 操作确认卡片 + 结果模拟），认证人员可完整走查。
- **历史记录**：仅本地 `chrome.storage.local`，搜索/删除/导出。
- **用量感知**：本地估算每次消耗 token 与费用（用户花自己的钱，这是核心体验）。
- **隐私**：发送前内容预览/裁剪、隐私开关、敏感站点（网银/邮箱/健康）默认只读选区。
- **多语言**：`_locales` zh-CN + en-US，商店列表双语（决策 4）。
